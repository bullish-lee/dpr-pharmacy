# UI 가이드

> 외부 리서치를 종합해 만든 화면 규칙이다. 리서치는 세 갈래로 했다.
> - 시각 시스템: Toss TDS, Daangn SEED, Carbon, Primer, Stripe
> - 스캔·업무 흐름: Scandit, Lightspeed, GOV.UK 작업 목록, NN/g
> - 데스크탑 셸·스택: Wails·WebView2, Fluent, shadcn·Tailwind v4
>
> 실제 값은 `frontend/src/styles/index.css`와 `frontend/src/components/ui.tsx`에 있다.

## 1. 원칙
1. **잉크·흰 바탕·차가운 회색.** 파랑은 조작·정보에만 쓴다. 색은 조치가 필요한 곳에만 쓴다.
2. **금액은 색을 입히지 않는다.**
   - 한국 금융 관례에서 빨강은 증가, 파랑은 감소를 뜻해 혼동을 준다.
   - 2천 개가 넘는 빨간 숫자는 진짜 오류를 묻어버린다.
   - 심각도는 정렬 순서와 상위 20개 굵게로 표현한다.
3. **색 + 아이콘 + 단어**를 함께 쓴다. 색만으로 의미를 전달하지 않는다.
4. **추천은 중립적인 색으로** 보여준다. 초록 'OK'로 칠하면 사람들이 검토 없이 그대로 승인하게 된다.
5. **키보드 우선**으로 설계한다.
   - 단일 영문자 단축키는 쓰지 않는다. 한글 IME가 먹기 때문이다.
   - Enter, Space, Esc, 숫자, Ctrl 조합, F키만 사용한다.

## 2. 토큰
**글꼴**
- Pretendard Variable(앱 내장). 대체 글꼴: 맑은 고딕, Apple SD Gothic Neo.
- 숫자는 `tabular-nums`, 코드·제조번호는 `slashed-zero`.

**글자 크기**
- 페이지 제목 20/28 700
- 카드 제목 15 600
- 본문·표 14/20
- 레이블·배지 13 600
- 메타 12
- KPI 28/36 600

**간격·모양**
- 간격: 4px 단위. 페이지 24, 카드 20, 셀 좌우 12.
- 모서리: 입력·배지 6, 버튼 8, 카드·표 12, 대화상자 16.
- 그림자: 떠 있는 층(메뉴·저장 바·대화상자)에만 쓴다. 카드는 1px 테두리만.

**색상**

| 이름 | 값 |
|---|---|
| gray | 50 #F7F8FA, 200 #E2E6EA(구분선), 400 #8A94A0(입력 테두리), 600 #5C6672(보조 글), 900 #191E25(본문) |
| blue | 600 #1F5FE0(주 버튼·링크), 50 #EDF3FF(선택) |
| amber | 50/700: 확인 필요 |
| red | 50/700: 오류 전용 |
| green | 600: 완료 아이콘 |
| edit | #FFF6D5 + 왼쪽 3px amber 표식: 저장 안 한 변경 |

## 3. 표
- **크기와 구조**
  - 행 높이 40px, 헤더는 회색 배경에 고정.
  - 줄무늬는 넣지 않는다. 행 강조와 겹치기 때문이다.
  - 2천 행 이상은 가상 스크롤로 처리한다.
- **정렬**
  - 숫자는 오른쪽, 글자·배지·날짜는 왼쪽에 둔다.
  - 단위는 헤더에 한 번만 쓴다: "손실(원)".
  - 숫자 열은 처음 클릭할 때 큰 값부터 정렬한다. 사용자가 묻는 것은 "뭐가 제일 큰가"이기 때문이다.
- **빈 값:** 0은 "0"으로 쓰고, 없음은 빈칸으로 둔다. "-"는 쓰지 않는다.
- **실계수 입력칸**
  - 칸은 항상 보이게 둔다(더블클릭 편집 아님).
  - Enter는 저장하고 다음 행으로 이동한다. Esc는 되돌리고, 빈칸으로 저장하면 실계수를 삭제한다.
  - 입력하는 동안 행이 재정렬되지 않게 하고, 열을 벗어나면 다시 정렬하며 1초간 강조한다.
- **일괄 수정** (도매 기준)
  - 바뀐 칸을 강조하고, 하단에 고정된 "저장하지 않은 변경 n건 · 되돌리기 · 저장" 바를 띄운다.
  - 오류가 있으면 저장할 수 없다.

## 4. 배지 (색 = 필요한 조치의 정도)
| 상태 | 스타일 |
|---|---|
| 확인 필요 · 실제가 확인 필요 | amber 채움 + ⚠ (화면에서 가장 강함) |
| 실물보상 검토 | blue 채움 + 바코드 아이콘 |
| 서류보상 | 회색 채움 + 문서 아이콘 (다수라서 조용하게) |
| 완료 | 테두리만 + ✓ (뒤로 물러남) |
| 오류(급여 삭제 유예 없음 등) | red 채움 |

## 5. 스캔 화면
- **스캔 상태 표시:** 화면 위쪽에 "● 스캔 대기 중"을 표시한다. 스캐너 입력은 창 전체에서 받으며, 한/영 상태와 무관하게 물리 키로 복원한다.
- **'방금 스캔' 카드:** 상태 단어를 32px로 크게 보여준다. 상태는 다음과 같다.
  - 사입 도매(초록)
  - 도매 확인 필요(amber)
  - 매칭 없음(회색)
  - 이미 스캔(파랑)
  - 다른 약품·형식 오류(빨강)
- **소리 3종:** 성공, 주의·중복, 오류. 놀라지 않을 정도로 짧고 낮게 내며, 끌 수 있다.
- **확인 필요 처리:** 스캔을 멈추지 않는다(모달 금지). 기록 행에서 "1 가나약품 / 2 다라약품" 버튼으로 지정한다.
- **되돌리기:** Ctrl+Z로 마지막 스캔을 되돌린다.

## 6. 도매 앱 등록 화면
- **바코드 표시**
  - DataMatrix를 **한 번에 하나만** 크게 보여준다. 격자로 여러 개를 띄우면 휴대폰이 옆 코드를 읽는다.
  - 흰 바탕에 여백을 충분히 두고, 사람이 읽을 수 있는 (01)(17)(10)(21)을 함께 표시한다.
- **진행:** Space 또는 Enter를 누르면 '스캔완료 → 다음'으로 넘어간다. 타이머로 자동 진행하지 않는다.
- **위치 표시:** 진행률 막대, 포장 목록, 도매별 전환을 둔다.

## 7. 셸
- **사이드바:** 기본 232px이고 Ctrl+B로 56px 레일로 접는다. 창 폭이 1100px 미만이면 자동으로 접는다.
- **단축키:** Ctrl+1~9로 사이드바 순서대로 화면을 전환한다 (1 대시보드 · 2 약가인하 대응 · 3 고시 · 4 재고 · 5 약품 조회 · 6 데이터 가져오기 · 7 도매처·보상기준 · 8 처리 내역 · 9 설정). Ctrl + / Ctrl − / Ctrl 0 은 글자 크기.
- **창:** Windows 기본 타이틀바를 쓴다(스냅 레이아웃 유지). 최소 1024×560으로, 1366×768 화면에서 125% 배율까지 고려했다.
- **화면 배율 설정:** 87.5, 100, 112.5, 125, 137.5, 150%. html font-size를 조절하므로 rem 기반 전체가 함께 확대된다.
