**정리**
- 제조번호 → 도매를 알려주는 공개 데이터는 없다. 그래서 사입 근거(이팜 제조번호 포함 엑셀), 바코드, 사용자 확인을 조합한다.
- GTIN → 보험코드 추정 규칙의 정확도는 실측 97.0%다.
- 공식 매핑을 '매일' 주는 곳은 없다. 그래서 하루 한 번 새 판만 확인하고, 그 사이 새 바코드는 '추정 규칙 + 사용자 확인'으로 처리한다.
- 고시 단위(규격 '28'·'100(1)' 등)의 공식 근거: 「약제 급여 목록 및 급여 상한금액표」 제2조④⑤("생산규격단위로 등재", 분할조제용은 규격란에 "(1)"로 최소단위 가격). 실물(반품) 보상은 업계 관행상 미개봉·같은 제조번호만 받는다.

## 약제급여목록 (전체, 매달) — 자동 받기

- **출처:** 공공데이터포털 「건강보험심사평가원_약가기준정보조회서비스」 (#15054445, 무료, 라이선스 CC0).
  - 주소: `https://apis.data.go.kr/B551182/dgamtCrtrInfoService1.2/getDgamtList`
  - 응답(XML) 항목: 제품코드 `mdsCd`, 품목명 `itmNm`, 업체 `mnfEntpNm`, 규격 `nomNm`, 단위 `unit`, 상한가 `mxCprc`, 적용시작일 `adtStaDd`, 주성분코드 `gnlNmCd`, 투여경로·급여구분·전문일반, 바뀌기 전·후 코드
- **인증키:** 공공데이터포털에 가입하고 이 API를 활용신청하면 받습니다(개발계정은 하루 1만 건).
  - 앱 설정 → 자동 확인에 넣습니다.
  - 키는 이 PC의 설정에만 저장합니다. 오류 문장·기록·오류 보고에서 가립니다.
- **받는 방법:** 전체(약 2만 2천 품목, 쪽당 1000개)를 받습니다.
  - 이번 달 목록(적용일이 이번 달)을 받으면 그달에는 다시 받지 않습니다. 아직 지난달 목록뿐이면 하루 한 번 다시 봅니다.
  - 내용·적용일이 같으면 바꾸지 않습니다.
  - 실패하면 6시간 뒤 다시 시도하고, 장애마다 한 번만 알립니다.
- **바꾸지 않는 경우:** 받은 목록이 이상하면 지금 목록을 그대로 씁니다.
  - 전체 수(`totalCount`)만큼 다 받지 못함 (중간에 빈 쪽이 오면 끊긴 것으로 봄), 1000품목보다 적음
  - 지금 목록이 더 새것 (예: 시행 전에 직접 올린 다음 달 엑셀) — 실패가 아니라 그대로 둠
  - 품목 수가 지금 목록의 90% 미만, 또는 같은 제품코드의 고시 단위(규격·단위)가 5% 넘게 다름 — 한 번 알림
  - API 의 `nomNm`·`unit` 이 엑셀의 규격·단위와 같은 뜻인지는 아직 실제 키로 확인하지 못했습니다. 다르면 위 검사가 막습니다.
- **목록에서 빠진 품목:** 사입·조제·재고 기록이 있으면 지우지 않고 '지금 급여목록에는 없음'으로 둡니다 (`in_list = 0`). 지우면 단위 환산 기준이 사라져 재고 수량이 바뀝니다.
- **오류 응답 (2026-11-18 실제 서버로 확인):** XML `OpenAPI_ServiceResponse/cmmMsgHeader`
  - 인증키 없음: HTTP 401, `errMsg` = `SERVICE_KEY_IS_NULL`, `returnReasonCode` = 20
  - 등록되지 않은 키: HTTP 403, `errMsg` = `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`, `returnReasonCode` = 30 — 잘못 복사한 키와 승인 직후 키가 똑같이 옵니다
  - 다른 공공데이터 API 처럼 `errMsg` 가 `SERVICE ERROR` 이고 코드가 `returnAuthMsg` 에 오는 형식, 글자만 온 401·403 도 인증키 문제로 봅니다.
- **쓰지 않는 것:** 심평원 홈페이지의 엑셀은 프로그램 접속을 막으므로 자동으로 받지 않습니다. 직접 받은 엑셀은 가져오기에서 올릴 수 있습니다.
